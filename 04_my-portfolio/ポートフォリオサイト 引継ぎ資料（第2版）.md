## 6. 起きたトラブルと対処（記録）

- **コミットが作られず push が失敗（`src refspec main does not match any`）**：`git add` をしていなかったのが原因。`git add .` のあとにコミットする
- **push が拒否（`non-fast-forward`）**：GitHub側にREADME等の初期ファイルがあり、手元と履歴が食い違った。`git pull --rebase origin main` のあとに push する
- **Cloudflareのビルド失敗（`error occurred while updating repository submodules`）**：zip展開でできた入れ子の `my-portfolio/`（中に `.git` がある）がサブモジュール扱いになる場合や、push前の古いコミットを取りに行った場合に起きる。`git ls-files -s | grep 160000` で確認し、出れば `git rm --cached 名前` で外す。今回は何も出ず、push完了後に解消
- **Cloudflareの初期設定がWorkers形式**：Build command が `None`、Deploy command が `npx wrangler deploy` になっていた。`wrangler.jsonc` を追加し、Build command を `npm run build` にして対応
- **URLが `my-portfolio.home-dashboard-trash53.workers.dev` になる**：`workers.dev` のサブドメインはアカウント共通で、最初のPWAプロジェクトで決まったもの。Workers & Pages の概要ページ（Account details）から変更できる。変更すると、アカウント内のすべてのWorkersのURLが変わり、古いURLは使えなくなる（home-dashboard のPWAをホーム画面に追加している場合は追加し直し）

## 8. 注意点・リスク

- 右クリック防止はスクリーンショットや開発者ツールでの取得を防げません。実質的な保護はウォーターマークが担います。
- `robots.txt` はお願いベースです。複数の対策を併用しています。
- OGP画像はSNSのクローラーが取得するため、作品画像とは別フォルダ（`public/ogp/`）に置き、クロール対策から除外します。
- 公開後に、実際の画像でEXIF（GPS・日時）が残っていないことを確認してください。
- 同意書・身分確認の記録はサイトに載せず、手元で保管します。
- 作品画像がリポジトリに入るため、GitHubリポジトリは Private を推奨します。
- 最初の4枚は `loading="eager"`、それ以降は遅延読み込みです。
- Cloudflareの設定変更だけではビルドの内容は変わりません。コードを直したら、push してから Retry build を使います。

## 9. 運用手順

### 画像を追加する

1. ウォーターマーク入りの画像を `src/images/studio/` または `nature/` に、連番のファイル名（`001.jpg`, `002.jpg` …）で入れる
2. コミットして push する（GitHub Desktop の「Commit」→「Push origin」、またはターミナルで `git add .` → `git commit -m "add images"` → `git push`）
3. 数分で自動的に公開される

並び順を変えたいときは、ファイル名の番号を変更します。

### 変更を公開する（基本の流れ）

```bash
git add .
git commit -m "変更内容のメモ"
git push
```

push が、Cloudflareの自動ビルドのきっかけになります。
