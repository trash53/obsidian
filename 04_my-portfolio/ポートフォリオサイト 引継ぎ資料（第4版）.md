## 6. 起きたトラブルと対処（記録）

### 第3版までの記録

- **コミットが作られず push が失敗（`src refspec main does not match any`）**：`git add` をしていなかったのが原因。`git add .` のあとにコミットする
- **push が拒否（`non-fast-forward`）**：GitHub側にREADME等の初期ファイルがあり、履歴が食い違った。`git pull --rebase origin main` のあとに push する
- **Cloudflareのビルド失敗（`error occurred while updating repository submodules`）**：zip展開でできた入れ子の `my-portfolio/`（中に `.git` がある）がサブモジュール扱いになる場合などに起きる。`git ls-files -s | grep 160000` で確認し、出れば `git rm --cached 名前` で外す。今回は何も出ず、push完了後に解消
- **Cloudflareの初期設定がWorkers形式**：Build command が `None`、Deploy command が `npx wrangler deploy` になっていた。`wrangler.jsonc` を追加し、Build command を `npm run build` にして対応
- **URLが `〜.workers.dev` になる**：`workers.dev` のサブドメインはアカウント共通。Workers & Pages の概要ページから変更できる。変更すると、アカウント内のすべてのWorkersのURLが変わり、古いURLは使えなくなる。今回は変更済み
- **フォーム送信で「Invalid Form ID/Access Key」**：公開ページに実際に出力されているキー（ページのソースで `access_key` を検索）と、メールで届いたキーを照合して対応した。**curl でのAPIテストは、無料プランでは「サーバー側からの送信は不可」となるため、キーの検証には使えない**。テストは公開ページのフォームから行う
- **拡大表示で画像が原寸のまま大きく出る（デスクトップ）**：`.modal` のグリッドの行の高さが固定されておらず、`max-height: 100%` が効かなかった。`.modal` に `grid-template-rows` / `grid-template-columns: minmax(0, 1fr)` を指定し、`.stage` を `width/height: 100%`、`.stage img` を `max-width: 90vw`・`max-height: 90dvh` にして解消

### 第4版で追加

- **`Could not import ../lib/orderImages`（FailedToLoadModuleSSR）**：`src` の中のフォルダ名が `liv` になっていた（正しくは `lib`）。名前を `lib` に直して `npm run dev` を再起動して解消
- **`Base.astro` で CompilerError（Unexpected token）**：`{条件 && ( ... )}` の中に、HTMLコメントと `<script>` を並べて書いたのが原因。コメントを削除して解消。Astroの式の中にHTMLコメントを書かない
- **Cloudflare Web Analyticsの設定**：Pagesと違い、Workers形式では自動設定に頼らず、**手動でスニペットを入れる**。ダッシュボードの Web Analytics → Add a site で、公開URLのホスト名（`https://` と末尾の `/` なし）を入力してトークンを取得し、`config.ts` の `ANALYTICS_TOKEN` に設定する。入力したホスト名と実際のホスト名が違うと計測が弾かれる
- **CloudflareのAIボットブロック**：ダッシュボードの「Security」配下の設定（Block AI bots）は、自分のドメイン（ゾーン）が対象。独自ドメインなしでは項目が出ない、または設定できない可能性が高い。確認方法：ダッシュボードの Security に Bots / Block AI bots が出るか、ドメイン選択を求められるか。出ない場合は `robots.txt` の対応で代替する

## 8. 注意点・リスク

- 右クリック防止はスクリーンショットや開発者ツールでの取得を防げません。実質的な保護はウォーターマークが担います。
- `robots.txt` はお願いベースです。守らないクローラーは止められません。複数の対策を併用しています。
- OGP画像はSNSのクローラーが取得するため、作品画像とは別フォルダ（`public/ogp/`）に置き、クロール対策から除外します。
- 公開後に、実際の画像でEXIF（GPS・日時）が残っていないことを確認してください。
- 同意書・身分確認の記録はサイトに載せず、手元で保管します。
- 作品画像がリポジトリに入るため、GitHubリポジトリは Private を推奨します。
- 最初の4枚は `loading="eager"`、それ以降は遅延読み込みです。
- Cloudflareの設定変更だけではビルドの内容は変わりません。コードを直したら、push してから Retry build を使います。
- Web3Formsのアクセスキーと、Web Analyticsのトークンは、ページに出力される前提の公開値で、秘密情報ではありません。ただし、Web3Formsは取得時のメールが再発行に必要なので残しておきます。
- Web Analyticsは広告ブロッカーに遮断されるため、実際の閲覧者の一部は計測から漏れます。自分で確認するときは、拡張機能を切るかシークレットウィンドウを使います。
- 将来 `public/_headers` にCSPを追加する場合は、`static.cloudflareinsights.com` からのスクリプト読み込みと、`cloudflareinsights.com` への送信を許可する必要があります。
- サイト上のAboutのガイドラインは、書面の同意書の**代わりにはなりません**。
- 私（Claude）はコードの表示確認やビルドを手元で実行できていません。ファイルを差し替えたら、`npm run dev` で表示を確認してから push してください。

## 9. 運用手順

### 画像を用意する基準

| 項目 | 目安 |
| --- | --- |
| 長辺 | 2000px前後（最大でも2400px） |
| 形式 | JPEG（sRGB） |
| 品質 | 80〜85 |
| 1枚の容量 | 300〜600KB、大きくても1MB以内 |
| 比率 | 元の比率のまま（トリミングしない） |

- 元データ（原寸）は、リポジトリの外に別保管する
- 先にリサイズし、**そのあとに**ウォーターマークを入れる
- 書き出し時に EXIF（GPS・撮影日時など）を削除する（Lightroomのメタデータ設定で「著作権情報のみ」など）
- ギャラリーは `astro:assets` で、グリッド用（幅600px）と拡大用（幅2000px）のWebPをビルド時に自動生成する。サムネイルを別に用意する必要はない

### 画像を追加する・並び順を変える

1. ウォーターマーク入りの画像を `src/images/studio/` または `nature/` に入れる（ファイル名は任意。例：`08.jpg`）
2. `src/gallery-order.ts` のリストで、表示したい位置にファイル名を1行足す。**途中への差し込みも、行を足すだけ**
3. 順番を変えるときは、リストの行を上下に移動する（ファイル名は変えなくてよい）
4. コミットして push する
5. 数分で自動的に公開される

- リストに書き忘れた画像は、いちばん最後にファイル名順で表示される（消えない）
- リストにあるのに画像がない場合、その行は無視され、ターミナルに警告が出る（打ち間違いの発見に使える）
- 非表示にしたい画像は、リストから消し、`src/images` の外に移動する（`src/images/studio/delete/` のようなサブフォルダは読み込まれない）

### 変更を公開する（基本の流れ）

```bash
git add .
git commit -m "変更内容のメモ"
git push
```

push が、Cloudflareの自動ビルドのきっかけになります。

### 解析の見方

Cloudflareダッシュボードの Web Analytics で、登録したサイトを開く。計測を止めたいときは、`config.ts` の `ANALYTICS_TOKEN` を空文字にする。
