# nurojunk (VSinger Fan Site) 仕様書

---

## 1. プロジェクト概要

* **サイト名:** nurojunk (非公式ファンサイト)
* **目的:** VSinger「nurojunk」のファン活動（推し活）をサポートするため、締め日情報（チケット・グッズ等）の一括確認・マイリスト管理、ディスコグラフィおよび歌配信のセットリスト検索を提供する。
* **運用方針:** 
  * 公式権利者に配慮した**完全非営利**での運営。
  * コスト・メンテ負担を最小化するため、CloudflareエコシステムおよびAstroを活用したモダンかつエッジファーストなアーキテクチャを採用。

---

## 2. コア機能要件

### 2.1 締め日アグリゲーター（メイン機能）
* **機能:** 
  * チケット先行/一般受付、限定グッズ受注、デジタルボイス販売などの締切日を一元表示。
  * **表示形式:** リスト/タイムライン表示（「あと〇日」カウントダウン付き）および月間カレンダー表示。
  * **カテゴリタグ:** `グッズ`, `チケット`, `ボイス・コンテンツ`, `イベント` 等。
* **マイリスト・チェック絞り込み機能（ローカル状態管理）:**
  * 各アイテムにチェックボックスを設置。
  * ユーザーが追いたい項目のみを絞り込んで表示する「マイリスト」切り替え。
  * チェック状態は `localStorage` に保存し、ログイン不要で永続化。

### 2.2 サブ機能（アーカイブ＆検索）
* **ディスコグラフィ:** リリース曲・公式MV・カバー曲のカタログ化（YouTube/各種配信サービスへのリンク）。
* **歌配信セットリスト検索:**
  * 「どの配信の何分頃にどの曲が歌われたか」「曲ごとの過去歌唱回数」を検索・閲覧可能。
  * テキスト主体のデータベース検索UI。

### 2.3 X (旧Twitter) リマインド運用（ハイブリッド方式）
* **自動投稿APIは採用せず**、X APIの制限やコスト回避のため**ハイブリッド運用**を行う。
* **投稿ロジック:**
  * バックエンド / GAS / Worker 等で毎朝「本日の締め日一覧（またはカウントダウン文面）」を自動生成。
  * 生成されたテキストを運営者の通知環境（Discord/Slack/LINE等）へ自動送信。
  * 運営者が文面を確認・コピーし、Xの公式機能（即時ポストまたは無料の予約投稿機能）を用いて手動投稿。
* **対象選定:**
  * 重要度の高いアイテム（チケット・限定グッズ等）に限定し、タイムラインの過度な更新を防ぐ。

## 3. UI/UX・著作権保護設計

### 3.1 初回アクセス時の「免責事項モーダル」
* **目的:** 公式サイト・運営との誤認防止、および著作権・免責に関する明確なクッションページ設置。
* **制御ロジック:**
  * 初回訪問時のみ画面全体にモーダルを表示し、同意ボタンの押下を要求。
  * 同意状態は `localStorage` (`nurojunk_disclaimer_accepted = 'true'`) に保存。
  * 2回目以降の訪問時には自動的に非表示化。

### 3.2 権利者保護・ガイドライン準拠
* **非公式明記:** ヘッダー・フッターおよび免責モーダルに「非公式ファンサイト」である旨を明記。
* **画像データの取り扱い:** 
  * 公式画像（ロゴ・イラスト・ジャケット等）の直接保存・複製掲載は避け、テキスト情報をメインに構成。
  * 視覚的コンテンツが必要な場合は YouTube / X の公式埋め込み機能（Embed）または公式ストア（BOOTH等）へのハイパーリンクを使用。
* **無収益化:** 広告（AdSense/アフィリエイト等）や投げ銭機能は一切設置しない。

## 4. 技術スタック・アーキテクチャ

| レイヤー | 採用技術 | 選定理由 |
| :--- | :--- | :--- |
| **フロントエンド** | **Astro** (+ React/TypeScript) | 静的表示の爆速化と、インタラクティブ部分（React Isles）のハイブリッド運用に最適。ポートフォリオ開発の知見をそのまま活用可能。 |
| **データベース** | **Cloudflare D1 (SQLite)** | エッジ動作で高速。無料枠が大きく、Cloudflare環境との親和性が抜群。 |
| **ホスティング/エッジ** | **Cloudflare Pages / Workers** | エッジデプロイによる高速配信およびCron Triggers（定期処理）の無料運用。 |
| **データ入力 / CMS** | **Notion API または 簡易管理画面** | 運営者が直感的に締め日や楽曲データを登録・管理できる構造。 |

## 5. データ構造案 (Cloudflare D1)

### `deadlines` テーブル
* `id`: TEXT (Primary Key)
* `title`: TEXT (例: 「〇周年記念アクスタ受注」)
* `category`: TEXT (`goods` | `ticket` | `voice` | `event`)
* `deadline_at`: DATETIME (締切日時)
* `official_url`: TEXT (公式ストアや申込み先リンク)
* `is_priority`: BOOLEAN (Xでのリマインド対象かどうか)
* `created_at`: DATETIME

### `songs` / `setlists` テーブル
* `id`: TEXT (Primary Key)
* `song_title`: TEXT
* `artist_name`: TEXT (原曲アーティスト)
* `stream_url`: TEXT (YouTube等のアーカイブURL)
* `timestamp`: TEXT (歌唱開始タイムスタンプ, 例: `01:23:45`)
* `sing_date`: DATE
