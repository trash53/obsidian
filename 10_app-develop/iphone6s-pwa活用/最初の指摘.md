### 1. 仕様書内・仕様書とHTMLの矛盾

- **エアコンの3操作が不一致**: 3.2は「冷房26℃ / 暖房22℃ / OFF」、4.2は「冷房26℃ / 冷房22℃ / OFF（冬は暖房に切替）」で、HTMLは3.2と同じです。どちらが正かを決める必要があります。季節切替を自動（月で判定）にするか手動にするかも未定義です。
- **解像度の表記**: 仕様書は1334×750、HTMLは667×375です。後者がCSSピクセル（@2x）で、実装上はこちらが基準になります。仕様書にも「CSS 667×375pt（物理1334×750）」と書くべきです。
- **HTMLの固定枠と確認用表記**: `.iphone-landscape` が667×375固定で、フッターに「667 × 375 px」というデバッグ表示が残っています。本番では `100vw/100vh` ベースに変え、この表示は削除してください。
- **細かな文言の揺れ**: 「消灯/停止/OFF」の表記が不統一です。見出しも仕様書は「今日・明日の予定」、HTMLは「予定一覧」で、「2 Events Today」は固定文字です。3.2の見出しには括弧の抜けもあります。

### 2. 不足している項目（実装前に決めたいもの）

**Obsidian連携（最大の欠落）**

- 読むファイルが未定義です（デイリーノートの `YYYY-MM-DD.md` か、専用の予定ファイルか）。
- 予定の書式が未定義です（例: `- [ ] 14:00-15:00 タイトル`）。
- サンプルUIにある「サブテキスト」「アイコン」「色分け」を、Markdownのどこから取るか（タグ、絵文字など）が未定義です。
- 終日予定、完了済みタスク、時刻なしタスクの扱いも決めてください。
- Obsidian→GitHubの同期手段（Obsidian Gitプラグインなど）と間隔が未定義です。反映遅延が予定表示の鮮度を決めます。
- GitHub PATは、対象リポジトリ1つ・Contents読み取りのみのFine-grained PATにし、有効期限切れの更新運用も決めてください。

**タイムゾーン**

- Workers上の日付はUTCなので、TODAY/TOMORROWの判定は明示的に Asia/Tokyo で行う必要があります。放置すると0〜9時に1日ずれます。

**エアコンの状態表示**

- SwitchBotのIR学習型エアコンは、Open APIで現在状態を取得できません。HTMLのアクティブ表示は「最後に押したボタン」でしかないため、その状態をどこに保持するか（端末localStorage、Workers KVなど）を決めてください。照明がHub接続のスマート機器なら状態取得できます。
- 「SwitchBot Hub」バッジが何を示すか（Hubの死活確認か、ただの固定表示か）も未定義です。

**更新・障害時の挙動**

- 予定の自動更新間隔、0時をまたいだTODAY/TOMORROWの切替、API失敗時の表示、オフライン時にService Workerでキャッシュした前回データを「最終更新時刻」付きで出すかどうかが未定義です。
- 連打対策（SwitchBot APIは1日10,000回の上限があります）やボタンの処理中表示も決めておくと安心です。

**iPhone 6s特有の制約**

- iPhone 6sはiOS 15.8.xが上限です。そのため **Tailwind CSS v4は使えません**（Safari 16.4以上が必要）。v3系を指定してください。
- マニフェストの `orientation` はiOSで無視されるので、「横画面固定」は仕様として実現できません。縦向き時に「横にしてください」と表示するオーバーレイを入れる案を推奨します。
- 常時表示するなら、自動ロックをオフにする設定、またはガイドアクセスの利用を運用手順に書いてください（Wake Lock APIはiOS 16.4以降のため使えません）。
- PWA用の `apple-mobile-web-app-capable`、`apple-touch-icon`、ステータスバー設定の記述も必要です。

### 3. 過剰・見直したほうがよい点

- **外部依存と「高速描画」の矛盾**: 仕様書は外部依存を排するとしていますが、HTMLはTailwind Play CDN（本番用ではなく、ブラウザ内でCSSを生成するため6sでは重い）と `unpkg.com/lucide@latest`（バージョン未固定）を読み込んでいます。Tailwindはビルドして静的CSSにし、アイコンは使う約12個をインラインSVGにするのが安全です。オフラインのPWAとしても必須です。
- **描画負荷**: A9チップで、背景のぼかしオーブ3つ、`backdrop-filter` のカード、`animate-pulse` の同時使用は重くなりがちです。オーブは1〜2個に減らし、pulseは止めることを推奨します。
- **文字サイズ**: `text-[9px]`〜`[10px]` が多用されています。壁掛け用途なら、本文は11〜12px以上にしたほうが読めます。`user-scalable=no` もiOS 10以降は無効です。
- **Pages + Workers**: 現在は静的アセット付きのWorkers単体で完結できるため、構成を1つにまとめる選択肢があります。

### 4. セキュリティ面の補足

- **コマンドのホワイトリスト化**: `/api/switchbot` は任意のコマンドを中継せず、`light_full`, `ac_cool26` のような固定IDだけを受け取り、deviceIDやコマンド内容はWorkers側で変換してください。
- **簡易構成のトークン**: URLパラメータに入れると履歴やログに残るため、ヘッダーかCookieにしてください。
- **機密情報の置き場所**: `GITHUB_TOKEN` などはプレーンな環境変数ではなくSecretsとして登録してください。
- **Cloudflare Accessのセッション**: 壁掛け端末でPIN入力が頻発しないよう、セッション期間を長めに設定してください。また、iOSのスタンドアロンPWA、Service Worker、Accessのリダイレクトは相性問題が出やすいので、早めに実機で検証してください。
