## 3. 決定事項の要約

| 項目 | 決定内容 |
| --- | --- |
| 端末 | Fire 7 (9th Gen)、1024×600、液晶(IPS)。日中は開発者オプションでスリープなし、夜間はスリープして朝に解除 |
| ホスティング | GAS Webアプリ（HtmlService）で画面も配信。「自分のみアクセス可」でデプロイ。GitHub Pagesは使わない |
| 室温・湿度 | SwitchBot Cloud API v1.1 をGASサーバー側から呼ぶ。ブラウザは `google.script.run` で取得。60秒キャッシュ |
| 天気・外気温 | Open-Meteoをブラウザから直接取得（山陽小野田市 北緯34.03・東経131.18）。3時間おき |
| 24h温度グラフ | 外気温（Open-Meteoのhourly）。当日0〜24時＋現在位置マーカー。室温履歴の記録はしない |
| レイアウト | 左600×600が同心円時計、右424×600に室温・湿度・天気・グラフ。時計サイズは定数で調整可能 |
| 時計 | 秒・分・時の3リング（時は12時間）。数字表示、AM/PM表示、日付表示はなし |
| 配色の対応 | 時リング＝室温カード、分リング＝湿度カード、秒リング＝天気アイコンと外気温グラフ |

| 時刻基準 | Asia/Tokyo（UTC+9固定オフセット）。0時に3秒でフェード遷移 |
| 描画 | 30fps上限。発光は `shadowBlur` を使わず、重ね描き疑似Glow。時・分リングは別Canvasで1秒ごと更新 |

## 4. 色生成アルゴリズム（要点）

詳細は仕様書5章。

- OKLCH色空間を使用。L 0.76〜0.86、C 0.11〜0.17に固定し、黒背景で沈む色を構造的に排除する。sRGB範囲外はCを二分探索で下げる。
- シード: JST日付文字列を xmur3 で32bit化し、mulberry32 に渡す。乱数の消費順は「基準色相 → 配色スキーム → 明度・彩度のゆらぎ」で固定。
- 配色スキームは類似色、トライアド、分裂補色の3種から日替わりで選択する。
- アクセント色はほぼ白（L 0.92、C 0.04）で、ラベルや小さい文字用。
- 前日の基準色相との差が40°未満なら+60°回転する。
- 確認用に、365日分のパレット一覧ページと `?date=YYYY-MM-DD` による日付指定デバッグを付ける。

## 5. 実装メモ

### 5.1 Code.gs の骨子（未検証のスケッチ）

署名の仕様やレスポンスの項目名は、実装時にSwitchBot公式ドキュメントで確認すること。

```javascript
function doGet() {
  return HtmlService.createHtmlOutputFromFile('index')
    .setTitle('Ambient')
    .addMetaTag('viewport', 'width=device-width, initial-scale=1');
}

function getSensor() { // google.script.run から呼ぶ
  const cache = CacheService.getScriptCache();
  const hit = cache.get('sensor');
  if (hit) return JSON.parse(hit);
  const p = PropertiesService.getScriptProperties();
  try {
    const token = p.getProperty('TOKEN');
    const secret = p.getProperty('SECRET');
    const id = p.getProperty('DEVICE_ID');
    const t = Date.now().toString();
    const nonce = Utilities.getUuid();
    const sign = Utilities.base64Encode(
      Utilities.computeHmacSha256Signature(token + t + nonce, secret));
    const res = UrlFetchApp.fetch(
      'https://api.switch-bot.com/v1.1/devices/' + id + '/status',
      { headers: { Authorization: token, sign: sign, t: t, nonce: nonce } });
    const b = JSON.parse(res.getContentText()).body;
    const out = { temp: b.temperature, humidity: b.humidity, ts: Date.now() };
    cache.put('sensor', JSON.stringify(out), 60);
    p.setProperty('LAST', JSON.stringify(out));
    return out;
  } catch (e) {
    const last = p.getProperty('LAST');
    return last ? JSON.parse(last) : null;
  }
}
```

- デバイスIDは `GET /v1.1/devices` で調べてスクリプトプロパティ `DEVICE_ID` に登録する。トークンとシークレットはSwitchBotアプリの開発者向け設定から取得する。
- フロントはJSTの現在時刻と `ts` の差で「古さ」を判定する（室温・湿度15分超、天気6時間超）。

### 5.2 index.html の骨子

- 1つの `requestAnimationFrame` ループで、前回描画から33ms未満ならスキップして30fpsにする。
- フレーム内で配列やオブジェクトを生成しない。DOMノードを増やし続けない。
- 天気は `daily.time` がJSTの今日・明日と一致するものを探して表示する。一致しなければ `--` を出し、即時再取得する。
- Open-Meteoのリクエスト: `daily=weather_code,temperature_2m_max,temperature_2m_min&hourly=temperature_2m&timezone=Asia/Tokyo&forecast_days=2`
- 天気コードのマッピングは仕様書10章。アイコンは自作の単色線画SVGで、秒リング色を適用する。
- `visibilitychange` で復帰を検知し、日付再判定、テーマ更新、データ再取得を行う。朝の復帰時に1日1回の自動リロードも行う。
- `?debug=1` でfpsとメモリを小さく表示する（通常は非表示）。
- 左パネルは `height` 基準の正方形、残りを右パネルとする相対レイアウト。

## 6. 注意点とリスク

1. **GASのログイン切れ**: 「自分のみ」公開のため、Fire 7のGoogleログインが切れると画面が出ない。数日運用して頻度を確認し、頻発するなら別構成（GitHub Pages＋GAS等）に切り替える。
2. **GASのiframe表示**: ページはiframe内に表示されるため、全画面表示、viewport、自動リロードが想定どおり動くか仮実装で検証する。
3. **Open-Meteoのfetch**: GASのiframe（サンドボックス）内から通るか未確認。通らない場合は、GAS側で `UrlFetchApp` から取得し `google.script.run` で渡す。
4. **細いフォント**: Fire 7は約171ppiのため、Thin(100)は大きな数値のみに使う。ラベルは weight 200〜300、16px以上。
5. **コード更新時の再デプロイ**: GASはコードを変えるたびに、既存デプロイを編集して新バージョンを公開する必要がある（URLを変えないため）。
6. **Open-Meteo**: 無料枠は非商用限定で、本用途は1日約8回と上限に十分余裕がある。帰属表記の要否は規約本文で確認する（ユーザーが確認予定）。
