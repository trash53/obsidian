# Obsidian Hub 引き継ぎ資料

作成日: 2026-10-31 / 次のチャットの Claude へ。最初にこの資料と、あわせて渡される「Obsidian Hub システム仕様書 v2」を読んでください。

## 1. プロジェクトの目的

スマホ（iPhone SE 3 / Chrome）から Obsidian（GitHub リポジトリ管理）へ、予定・ログ・Webクリップを書き込む PWA を作る。加えて Gemini API のチャット UI を内蔵し、**会話の要約をデイリーノートに蓄積して、あとで見返せるようにする**のが主目的。

## 3. ユーザーが確定させたこと（要点）

- 環境: iPhone SE 3 + Chrome。PWA としてホーム画面に追加して使う。
- 認証: Cloudflare Zero Trust のメール OTP。
- ホスティング: Workers (Static Assets)。DB は D1、定期処理は Cron（5 分ごと）、案 A 採用。
- 日付は JST。ファイル名は `YYYY-MM-DD_タイトル.md`、フォルダは `30_calendar/events/` と `30_calendar/daily-note/`。
- 予定は 1 件 1 ファイルで新規作成のみ（追記なし）。終日と時間指定を選べて、時間指定のときだけ時刻欄を出す。Full Calendar プラグイン対応の frontmatter を使う。
- 書き込みは「最新を再取得 → 再追記」方式（409/422 は最大 3 回リトライ）。
- オフライン時は入力を IndexedDB に保存し、次回通信時にまとめて送信する。起動時にオフラインならメッセージを表示する。
- チャットは複数同時進行。チャットごとに最後のメッセージから 30 分で要約する。日をまたいだら、開始日のデイリーノートに書く。再開後の部分は再開日に「（続き）」付きで追記する。
- 要約の形式: タイトル、要点の箇条書き、決定・TODO。全文ログは Obsidian に保存しない。
- トークンは多少精度が落ちても余裕を持つ方針。段階的要約（rolling summary）を使う。
- TODO は期限付きのものを確認カードで承認したときだけ、終日予定として登録する（自動登録はしない）。
- 親指ファーストを最優先にする。実装前にモックを確認する流れは完了済み。

## 4. モックの修正点（本実装で必ず直すこと）

1. 日付・時刻の入力欄がカードの右端からはみ出す。`min-width: 0`、`max-width: 100%`、`-webkit-appearance: none` を指定する。
2. 「見送り」ボタンが 2 行に折れる。`white-space: nowrap` と `flex: none` を指定し、ボタン幅を揃える。
3. チャットタブでスクロールしても「＋新しいチャット」を画面下部（タブの真上）に固定表示する。一覧の末尾が隠れないよう下余白を確保する。

## 5. iPhone 固有の制約（設計に影響）

- Web Share Target は使えない。代わりに、アプリ内の貼り付けボタンと iOS ショートカットで Web クリップを受ける。
- Background Sync は使えない。アプリを閉じている間は未送信分が送られない。
- PWA とブラウザで、ログイン状態とストレージが別になる。
- 長期間使わないと Web アプリのデータが消えることがある。未送信分は早めに同期する。

## 6. 未決事項（ユーザーに確認が必要）

- 既存のデイリーノートのテンプレート（見出し名・frontmatter）。**貼ってもらう予定**。
- ログの追記形式（`- HH:mm 本文` は案）。
- 要約成功後に全文をすぐ削除するか、7 日残すか。
- 使う Gemini モデル、無料枠のレート制限と利用規約。
- Full Calendar のタスク形式（`completed: false`）が実機で動くか。
- ショートカットから API を呼ぶときの認証（Access のサービストークン）。
- ホーム画面に追加するのを Chrome と Safari のどちらにするか。

## 8. ユーザーとの進め方（留意点）

- 日本語で、簡潔に回答する。スマホの画面で読むため、長すぎない構成にする。
- 仕様が曖昧な点は、決め打ちせず提案して確認を取る。ユーザーは決定事項と未決事項を明確に分けている。
- 実装前にモックで確認する、という流れを重視している。大きな画面変更は、先にモックで見せる。
- ユーザーは「親指ファーストが他の仕様と競合したら親指ファーストを正とする」と明言している。
- 最初にアップロードされた HTML サンプルは「ビジュアルサンプル」であり、機能の実装根拠ではない。仕様書 v2 とモックが正。
- 元の仕様書（Gemini が作成し手で修正したもの）の破損箇所は、ユーザーが無視してよいと回答済み。
